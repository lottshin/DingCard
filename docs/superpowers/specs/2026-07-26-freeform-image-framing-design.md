# 自由编辑图片取景设计

## 1. 背景

自由编辑器目前只提供“填满”和“适应”。选择“填满”后，图片始终居中裁切，用户无法把人物、商品或文字留在画面里；形状的图片填充也有同样的问题。

本次为独立图片元素和形状图片填充增加无损取景。原图不改写，草稿只保存焦点和缩放值。画布、页面缩略图和 PNG 导出必须使用同一套计算。

## 2. 范围

本次包括：

- 独立图片元素的取景。
- 矩形、椭圆和三角形图片填充的取景。
- 画布内拖动、缩放、重置、完成和取消。
- 旧自由编辑草稿迁移、本地与远程保存、复制、页面复制和导出。
- 桌面与窄视口、浅色与深色主题、普通节点与嵌套组节点。

本次不做图片滤镜、旋转图片内容、自由路径蒙版、位图裁剪、批量套用取景或新的后端接口。

## 3. 方案选择

采用“归一化焦点 + 相对缩放”：

```ts
interface ImageFraming {
  focusX: number
  focusY: number
  zoom: number
}
```

`focusX` 和 `focusY` 表示原图中希望留在取景框中心的位置，范围为 `0..1`；`zoom` 相对于刚好填满容器的基础倍率，范围为 `1..4`。默认值为 `{ focusX: 0.5, focusY: 0.5, zoom: 1 }`。

没有采用另外两种方案：

- 保存像素偏移：元素改尺寸或复制到另一种比例后，原偏移失去含义。
- 生成裁切后的新图片：会丢失原图，增加存储和回收成本，也无法随时恢复取景。

归一化数据与容器尺寸无关，能在调整元素尺寸、改变形状和组缩放后继续使用。

## 4. 文档契约与迁移

### 4.1 v4 文档

自由编辑文档升级为 `documentVersion: 4`。`framing` 在两类图片数据中都是必填字段：

```ts
interface FreeformImageElement extends FreeformElementBase {
  type: 'image'
  src: string
  alt: string
  fit: 'cover' | 'contain'
  framing: ImageFraming
}

type ShapeFill =
  | ColorPaint
  | {
      type: 'image'
      src: string
      fit: 'cover' | 'contain'
      framing: ImageFraming
    }
```

运行时不保留可选 `framing`。新建图片、新建图片填充以及迁移后的旧图片都拿到一份独立的默认对象，避免共享可变引用和到处补 fallback。复制节点、复制页面、迁移、物化和上传映射也必须深复制 `framing`，不能用对象展开保留同一个嵌套引用。

严格 v4 归一化拒绝以下输入：缺少字段、多余字段、`NaN`、`Infinity`、焦点越界、缩放小于 1 或大于 4。拒绝整份文档，不把部分修复后的 v4 数据送进工作区。

### 4.2 迁移路径

读取入口统一返回 v4：

1. v1/v2 继续通过现有平面元素迁移生成合法场景树。
2. v3 先按原契约校验，再递归给独立图片和图片填充加入默认取景。
3. v4 走严格克隆和校验，不使用旧版本的宽松 fallback。
4. 不支持的版本直接拒绝。

迁移不修改输入对象，必须覆盖隐藏节点和任意合法嵌套深度。`DraftEnvelope.schemaVersion`、SQLite 结构和草稿 API 不变；服务端仍把自由编辑文档作为 JSON 保存。

只在历史格式的校验与迁移函数上保留版本后缀。表示当前运行时的类型、reducer 和场景遍历函数改用无版本名称，避免下一次文档升级继续遗留 `V3` 名称。

## 5. 取景计算

新增纯模块 `imageFraming.ts`，集中提供默认值、校验、相等判断、渲染几何和拖动换算。组件不能各自实现一套公式。取景相等判断逐项使用 `1e-6` 容差；持久化时保留计算精度，不按界面显示值取整。

设原图尺寸为 `Iw × Ih`，取景框为 `Fw × Fh`。

“填满”模式：

```text
baseScale = max(Fw / Iw, Fh / Ih)
scale = baseScale * zoom
Rw = Iw * scale
Rh = Ih * scale

rawX = Fw / 2 - focusX * Rw
rawY = Fh / 2 - focusY * Rh
left = clamp(rawX, Fw - Rw, 0)
top  = clamp(rawY, Fh - Rh, 0)
```

图片按 `Rw × Rh` 绝对定位到 `left/top`。`zoom >= 1`，再配合边界夹取，任何合法状态都不会露出空白。

“适应”模式使用 `min(Fw / Iw, Fh / Ih)` 并居中，完全忽略 `framing`，但不删除或改写它。

拖动时先把屏幕位移通过现有场景矩阵的逆变换转换为目标节点的本地位移，不能只除以画布缩放。图片位置按本地位移移动并夹取，再反算焦点：

```text
focusX = clamp((Fw / 2 - left) / Rw, 0, 1)
focusY = clamp((Fh / 2 - top) / Rh, 0, 1)
```

因此旋转节点、缩放组和嵌套组中的拖动方向仍与用户看到的图片一致。元素改尺寸或形状改变时不改持久化数据，只用新容器尺寸重新计算并夹取。

纯计算函数先检查原图、取景框、缩放和矩阵输入。原图或取景框宽高不是正有限数、画布渲染比例不是正有限数、场景世界矩阵含非有限值或不可逆时，几何函数返回 `null`，拖动函数返回原取景引用；不得产生 `NaN` 或部分更新。现有文档校验已经保证叶子宽高和有效缩放合法，但调用边界仍保留这些检查。

图片尚未解码或任一前置条件不满足时不能进入取景。若视口或文档状态在会话中令条件失效，撤回当前拖动并安全取消整次会话，文档不变。展示层不能用居中裁切冒充已经保存的非默认取景：`contain` 或默认取景可以使用与主路径等价的居中 `object-fit`；非默认 `cover` 在没有可用原图尺寸时显示中性加载面，已有同源尺寸时继续按精确几何渲染。

## 6. 共享渲染

新增 `FramedImage` 展示组件，独立图片和形状图片填充都通过它渲染。组件负责：

- 解析图片引用并读取原图宽高。
- 按 `imageFraming.ts` 的结果定位图片。
- 图片尚未解码时只使用第 5 节规定的等价 fallback 或中性加载面，不能短暂显示错误取景。
- 编辑画布、页面缩略图和仅展示模式使用相同 DOM 结构。

只有活动画板中的可编辑 `FramedImage` 向工作区报告解码状态；页面缩略图和仅展示实例不参与入口判断。报告使用 `{ scopeGeneration, slideId, scenePathKey, logicalSrc, resolvedSrc }` 作为完整身份，内容为 `loading | ready | error`，`ready` 同时携带正有限的 `naturalWidth/naturalHeight`。工作区只接受仍与当前草稿作用域、节点路径、节点类型和图片源完全匹配的报告，并把这份尺寸快照写入取景会话。

`FramedImage` 每次 `resolvedSrc` 改变或卸载时递增本地 generation，并先报告 `loading`。`load`、`decode()` 成功或失败的回调必须同时匹配 generation 和当前源才能上报；旧图片的迟到结果直接丢弃。工作区的状态表在节点消失、活动页面变化或草稿作用域变化时删除对应记录，不跨草稿复用路径相同的状态。

独立图片使用一个裁切容器包住真实 `<img>`。形状图片填充不再依赖 CSS `background-image`，而是在现有形状容器中放入同一个 `FramedImage`；容器继续负责圆角、椭圆或三角形裁切和描边。纯色与渐变形状仍走现有 paint 样式。

取景辅助线、操作条和选中轮廓全部放在 `freeform-ui-only` 层，不进入缩略图和导出。

导出调用 `html-to-image` 前等待当前画板中的图片完成 `decode()`，再等待两个 animation frame，让精确几何完成渲染。任何图片解码失败或超时时，本次导出失败并显示现有操作错误，文档保持不变；等待不能无限挂起，仍需满足现有 5 秒导出验收上限。换源期间的旧 `decode()` 结果不能让新图片进入 ready 状态。

## 7. 交互

### 7.1 进入和退出

满足以下条件时可以进入取景：

- 当前为单选的独立图片，或图片填充形状。
- 节点处于当前编辑作用域，且自身和祖先都未锁定、未隐藏。
- `fit` 为 `cover`，图片已经解码，没有正在进行的替换操作。

入口有两个：画布双击目标，或属性面板中的“调整取景”。组内节点沿用现有逐层进入作用域的规则，不额外穿透组层级。

取景模式不打开弹窗。目标上显示三等分辅助线；画布上方显示“取消”和“完成”，下方显示缩放控制。进入后焦点移到取景画布，原有选择框、移动、缩放和旋转手柄暂时隐藏。

- 拖动图片改变焦点。
- 缩放范围为 100% 到 400%，滑杆步长 1%，加减按钮每次调整 10%。
- 方向键按本地坐标把图片移动 1 px，`Shift` 加速为 10 px。
- `Enter` 完成，`Escape` 取消。
- 按钮和滑杆有可访问名称；图标按钮使用现有图标体系并提供 tooltip。

在窄视口中，顶部操作与底部缩放条必须留在工作区可见范围内，不覆盖彼此，也不能扩大页面横向滚动。

### 7.2 “填满 / 适应”规则

- “填满”显示并启用“调整取景”。
- “适应”禁用取景入口，tooltip 提示需切回“填满”；渲染忽略取景数据。
- 从“适应”切回“填满”后恢复之前的焦点和缩放。
- “重置取景”只恢复居中和 100%，不改变 fit。
- 替换图片只重置取景，不改变当前 fit；从纯色或渐变首次改为图片填充时默认使用“填满”。
- 修改元素宽高、修改形状类型、移动、旋转和组变换都保留取景数据。
- 复制节点、复制页面和保存恢复完整保留取景数据。

属性面板只在非默认取景时启用“重置取景”。在“适应”模式下保留数据，但隐藏或禁用重置入口，避免用户误以为适应模式会显示裁切效果。

## 8. 会话状态与历史

工作区维护一个临时取景会话，至少记录：草稿作用域标识、`slideId`、完整 `ScenePath`、目标类型、图片源、原图尺寸、开始时的文档快照和开始时的取景值。临时指针状态另存当前 pointer、拖动起点和拖动开始时的取景值，不写入草稿。

状态流转为：

```text
idle -> framing -> dragging -> framing
framing -> complete -> idle
framing -> cancel -> idle
```

拖动、滑杆、加减按钮和方向键都通过现有 `replaceCurrent` 实时更新。完成时：

- 最终值与开始值不同，调用 `commitLiveEdit(startDocument)`，整次会话只增加一条撤销记录。
- 最终值与开始值相同，调用 `cancelLiveEdit(startDocument)` 恢复原引用，不产生空历史。
- 取消或 `Escape` 调用 `cancelLiveEdit(startDocument)`，历史和已保存状态保持原样。

`pointercancel` 或窗口失焦只撤回当前这一段拖动，保留进入取景后已经完成的缩放和拖动；会话仍可继续。切换页面、草稿、账号或工作区时先取消整次取景，再执行切换。若草稿作用域已经变化，只清理临时会话，绝不能把旧快照写进新草稿。

取景期间只允许修改当前目标的 `framing`。选择、节点变换、fit、换图、填充类型、形状类型、描边、锁定、隐藏、新增、删除、粘贴、图层排序、撤销/重做、保存和导出全部暂停；属性面板和图层面板中的对应控件显示禁用状态，全局快捷键也不能穿透。用户先完成或取消，再执行这些命令。

页面、草稿、账号和工作区切换走同一个 `cancelFramingThenTransition` 入口，顺序固定为：核对旧作用域、按开始快照取消实时取景、清理会话与解码状态，再针对恢复后的文档执行页面切换，或装载新的草稿作用域。不能先切换或修改文档再恢复旧快照。若外部状态已经换到另一草稿作用域，只丢弃临时会话和旧解码状态，不向新作用域写入任何文档。

## 9. 更新契约与异步边界

独立图片的 `framing` 属于样式更新；形状图片填充继续作为完整 `fill` 值原子更新。所有 patch 都要通过 reducer 的类别白名单和严格数值校验。

新增 `cloneImageFraming` 和 `imageFramingEquals`，后者使用第 5 节的 `1e-6` 容差。图片填充不能继续使用当前浅层 `paintEquals`：`shapeFillEquals` 必须分别比较 `src`、`fit` 和嵌套 framing，所有复制函数也要创建新的 framing 对象。同值更新返回原节点引用，不得产生空历史。

独立图片 `src` 真正变化时，content reducer 同一次原子更新把 `framing` 设为默认值；只改 `alt` 不重置。形状替换构造新的图片 fill，并按第 7.2 节保留旧 fit、重置 framing。上传或读取失败时保留原图片、fit 和 framing。

图片替换沿用按“草稿作用域 + slideId + ScenePath”隔离的异步令牌。待处理替换存在时不能进入取景；迟到结果只有在草稿作用域、路径、节点类型和操作令牌都仍匹配时才能写回。正常 UI 在取景中不能删除、锁定、隐藏、换源或改变填充类型；若迟到的权威状态仍使目标失效，同一作用域内先丢弃实时取景并恢复会话开始快照，再应用权威更新，不同作用域只清理会话，不能恢复旧快照。

本次不增加 HTTP 错误码或状态码。加载和导出错误使用现有工作区错误提示。

## 10. 文件边界

计划中的职责划分如下：

- `types.ts`：v4 文档、`ImageFraming` 和 patch 类型。
- `imageFraming.ts`：默认值、校验、几何、拖动换算和相等判断。
- `FramedImage.tsx`：共享图片展示与解码状态。
- `sceneDocument.ts`：v1/v2/v3 到 v4 的迁移和严格 v4 归一化。
- `document.ts`、`sceneTree.ts`：原子更新、克隆和严格 mutation 校验。
- `FreeformSceneNodeView.tsx`：独立图片与形状填充接入共享组件。
- `FreeformWorkspace.tsx`：会话状态、历史、快捷键、入口和退出。
- `PaintField.tsx`：形状图片填充的取景与 fit 控件。
- `styles.css`：取景遮罩、辅助线和响应式控制条。

如果 `FreeformWorkspace.tsx` 中的会话逻辑超过一组局部状态和事件处理，应提取为专用 hook；不借本功能重构无关的选择、图层或导出流程。

## 11. 测试

### 11.1 单元测试

- 宽图、长图、方图和不同容器比例下的 cover/contain 几何。
- 焦点四角、最小/最大缩放、拖动越界和无空白保证。
- 零尺寸、非有限尺寸、无效渲染比例和不可逆矩阵稳定返回 `null` 或原引用。
- 屏幕位移经过旋转、画布缩放和嵌套组逆变换后的本地位移。
- v1/v2/v3 迁移到 v4；隐藏和嵌套图片也得到默认取景。
- v4 缺字段、多字段、非有限数和越界值整份拒绝。
- 新建、替换、重置、fit 切换、形状类型切换、克隆、页面复制和序列化。
- 独立图片和形状图片填充的 framing 深复制；同值 patch 返回原引用且不增加历史。
- 独立图片 src 更新与 framing 重置保持原子性；alt-only 更新不重置。
- 本地和远程草稿归一化行为一致。

### 11.2 Playwright 与集成测试

- 独立图片和形状图片填充都能从面板和双击进入取景。
- 拖动、缩放、方向键、完成、取消和 `Escape` 的视觉与历史结果。
- 一次会话只撤销一次；改回原值不产生历史。
- “适应”保留取景，切回“填满”恢复；替换图片保留 fit、重置取景。
- 元素改尺寸、形状改变、旋转节点和嵌套缩放组不露空白、不反向拖动。
- 锁定、祖先锁定、隐藏、异步替换和草稿切换不会误写文档。
- 图片解码失败、超时和换源后的迟到解码结果不会启用错误入口或污染新尺寸。
- 不同草稿复用相同 slide/path/src 时，旧 scopeGeneration 的解码结果仍会被拒绝。
- 非默认取景首次解码期间不出现错误的居中裁切，默认取景和 contain fallback 与最终画面一致。
- 页面缩略图、画布和导出使用一张带四角标记的测试图做像素对照。
- 本地保存恢复、远程保存恢复和迟到保存响应保留取景。
- 1440、1024 和 440 宽度，浅色与深色主题下控件不重叠。

最终运行 `npm test`、`npm run test:acceptance`、`npm run test:integration`、`npm run build` 和 `git diff --check`。视觉验收使用独立 Playwright Chrome，不操作用户正在使用的浏览器。

## 12. 文档与版本

这是新功能，根应用从 `0.13.5` 升到 `0.14.0`，同步根 `package.json` 与 `package-lock.json` 的根版本。后端没有代码或接口变化，`server` 保持 `0.3.0`。

同步更新 `docs/freeform-editor.md`、README、CHANGELOG、`docs/backend-plan.md` 和相关验收说明，写明 v4 契约、旧草稿迁移、取景规则和快捷键。模板注册表中的自由编辑文档也改为合法 v4。远端仓库、镜像和部署元数据不在本分支处理。

## 13. 验收标准

- 旧 v1/v2/v3 自由编辑草稿可读取并保存为 v4，坏 v4 不进入工作区。
- 用户能无损调整独立图片和形状图片填充，完成、取消、重置和撤销行为稳定。
- “填满/适应”、换图、改尺寸和形状变化严格遵守第 7.2 节。
