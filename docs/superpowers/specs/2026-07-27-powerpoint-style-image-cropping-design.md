# PowerPoint 式图片裁剪设计

## 1. 背景与目标

自由画布已经用 v4 文档实现无损图片取景。当前交互仍更像“移动图片 + 缩放滑杆”：取景框会裁掉框外原图，用户看不到可用画面；拖动时每个 `pointermove` 都经过 reducer 和 React 重渲染；`Escape` 被定义为取消。这些行为与 PowerPoint 的图片裁剪不一致，也是当前操作不够顺手的主要原因。

本次把**独立图片元素**改成 PowerPoint 式原位裁剪：黑色裁剪柄控制可见边界，拖动画面移动原图，框外仍能看到压暗的原图，点击外部或按 `Escape` 完成。形状图片填充继续使用现有“调整取景”，因为 Office 的标准图片裁剪工具并不等同于形状填充取景。

目标不是生成新的位图，而是在现有场景模型中复刻 PowerPoint 的主要操作和反馈，同时保留叮卡已有的保存、撤销、复制、导出和嵌套组能力。

## 2. 依据与范围

PowerPoint 式裁剪以微软 Office 图片裁剪说明为行为依据：

- 图片四边和四角出现黑色裁剪柄。
- 边柄裁一侧，角柄同时裁相邻两侧。
- 按住 `Ctrl` 拖动边柄时，两条平行边对称调整。
- 向外拖动裁剪柄可以找回先前隐藏的画面。
- 拖动图片可以改变图片在裁剪区域中的位置。
- 可以应用常用宽高比。
- `Escape` 或点击图片外部结束裁剪，并保留当前结果。
- 被裁掉的内容仍属于原图片，除非另行执行压缩或删除裁剪区域。

本次包括：

- 独立图片元素的原位裁剪、向外恢复、移动原图和比例预设。
- 普通节点、旋转节点、缩放组和嵌套组中的等价操作。
- 鼠标、触控笔、键盘和 440px 窄视口。
- 一次裁剪对应一次撤销记录。
- 保存、恢复、复制、页面复制、缩略图和导出保持一致。

本次不包括：

- 图片内容的独立旋转、透视、滤镜和自由路径蒙版。
- 删除原图中被裁掉的像素。
- 鼠标滚轮缩放和常驻缩放滑杆；它们不是本次复刻的 PowerPoint 核心操作。
- 把形状图片填充伪装成标准图片裁剪。形状仍保留现有“调整取景”入口和行为。
- 新的后端接口、HTTP 错误码或状态码。

## 3. 数据与兼容性

本次不增加持久化字段。独立图片继续保存：

```ts
interface FreeformImageElement {
  type: 'image'
  x: number
  y: number
  width: number
  height: number
  rotation: number
  fit: 'cover' | 'contain'
  framing: {
    focusX: number
    focusY: number
    zoom: number
  }
}
```

裁剪框就是图片元素的 `x/y/width/height`；原图在框内的位置继续由 `framing` 表示。拖动黑色裁剪柄时，几何和取景值必须在一次原子更新中共同变化。这样可以改变可见边界，同时让原图在画布上的位置和大小保持不动。

`documentVersion` 保持 `4`，`framing` 仍遵守现有严格校验和 `1..4` 缩放范围。裁剪柄在达到最小元素尺寸、原图边界或可表示的最大缩放时停止，不写入超范围值，也不露出空白。旧 v1/v2/v3 迁移、严格 v4 归一化和服务端 JSON 存储不变。

形状图片填充的数据和现有取景会话不变。独立图片和形状可以共用纯几何函数，但必须使用不同的界面名称和会话入口。

## 4. 裁剪几何

### 4.1 坐标系

裁剪计算在一个会话期间固定不变的“起始裁剪平面”中完成。该平面以进入裁剪时图片元素的左上角为原点，横纵轴跟随元素自身的未旋转轴；即使会话草稿随后改变了节点 `x/y/width/height`，平面的原点、方向和单位也不变。开始会话时记录：

- 草稿作用域、页面、完整 `ScenePath` 和目标图片源。
- 开始时的文档和图片节点快照。
- 原图自然尺寸。
- 起始裁剪平面到父级场景坐标的矩阵及其逆矩阵。
- 平面中的起始裁剪框 `C0 = [0, 0, width, height]` 和渲染原图矩形 `I0`。
- 当前会话草稿中的裁剪框 `C`、渲染原图矩形 `I` 与 `framing`。

屏幕位移先经过画布渲染比例和目标世界矩阵的逆变换，得到图片本地位移。不能只除以画布缩放，否则旋转节点和嵌套缩放组会出现方向或距离错误。

### 4.2 移动原图

在裁剪框内部按下并拖动时，只移动原图，不移动裁剪框。计算沿用 `panImageFramingFromScreen` 的边界约束；原图始终覆盖裁剪框，不得露出透明或页面背景。

方向键在裁剪画面获得焦点时移动原图 1 个本地像素，`Shift` 加速为 10 个。移动到边界后继续按键不产生空更新。

### 4.3 拖动黑色裁剪柄

八个黑色裁剪柄分为四个边柄和四个角柄：

- 边柄只移动对应的一条边。
- 角柄同时移动相邻的两条边。
- 按住 `Ctrl` 拖动边柄时，对侧边以中心为轴同步移动。
- 向内拖动隐藏更多画面；向外拖动只恢复当前原图矩形内仍可用的画面。

裁剪柄先在起始裁剪平面中产生原始边界。设手势开始框为 `Cstart`，原始指针结果为 `Craw`，手势路径定义为 `C(t) = lerp(Cstart, Craw, t)`，其中 `t` 为 `0..1`。每个候选统一经过约束：

1. 四条边和宽高必须是有限数，宽高满足现有最小元素尺寸。
2. 候选裁剪框必须完全位于当前会话草稿的渲染原图矩形 `I` 内。
3. 由候选框反算出的 `focusX/focusY/zoom` 必须满足 v4 契约，尤其是 `zoom <= 4`。
4. 任一矩阵、尺寸或反算结果无效时返回原草稿引用，不做部分更新。

合法结果不是依次夹取四条边，而是取集合 `{ t | C(t) 满足全部约束 }` 中**包含 `t = 0` 的连续区间**，再选择该区间内最大的 `t`。因此手势只在原图边界、最小尺寸、`zoom = 4` 或其他约束真正结束合法连续区间时停止，不能跳过非法区间，也不能因事件采样频率不同得到不同结果。cover 主导轴切换只是 `max()` 公式的分段点；只要回代和全部约束仍合法，手势必须连续通过，不能在切换点冻结。角柄两个方向同时越界、边柄 `Ctrl` 对称越界时也使用同一条一维手势路径投影规则。

投影后的裁剪框记为 `C = [L, T, R, B]`，当前会话原图矩形记为 `I = [IL, IT, IR, IB]`。设原图自然尺寸为 `Nw × Nh`，则：

```text
Fw = R - L
Fh = B - T
Rw = IR - IL
Rh = IB - IT
s = Rw / Nw = Rh / Nh
baseScale = max(Fw / Nw, Fh / Nh)
zoom = s / baseScale
focusX = (Fw / 2 - (IL - L)) / Rw
focusY = (Fh / 2 - (IT - T)) / Rh
```

`Rw / Nw` 与 `Rh / Nh` 在场景容差内必须相等。把反算结果重新传给 `calculateFramedImageGeometry` 后，得到的图片矩形必须在容差内等于 `[IL - L, IT - T, Rw, Rh]`；否则候选无效。这个回代检查保证节点框改变后，原图在画布上的矩形不会跳动。

候选框通过约束后，使用起始裁剪平面到父级的固定矩阵，把新框左上角和尺寸换算成节点 `x/y/width/height`。节点旋转角度不变；未被拖动的边在画布中的位置不变。节点几何与上述反算 `framing` 作为一个结果返回，组件不得分别计算。

### 4.4 比例预设

裁剪工具栏提供“比例”菜单：

- 原图
- 1:1
- 4:3
- 3:4
- 16:9
- 9:16

正常裁剪始终是自由比例，因此菜单不提供会造成状态歧义的“自由”命令。预设是一次性调整，不在会话或文档中保存比例锁；应用后仍可自由拖动任意裁剪柄。

应用比例 `r` 时，以当前裁剪框中心为锚点，计算**完全内接于当前裁剪框**的最大 `r` 比例矩形：当前框比 `r` 更宽时保留高度并收窄宽度，否则保留宽度并收窄高度。“原图”使用 `Nw / Nh`。候选框继续使用第 4.3 节的完整合法性与回代检查。若最小尺寸或 `zoom <= 4` 使目标比例无合法结果，整条命令失败且会话草稿不变，并使用现有操作提示说明原因；不能退化成一个近似比例，也不能只更新一条边。

## 5. 视觉与交互

### 5.1 进入裁剪

独立图片在以下条件下可进入裁剪：

- 当前是单选且处于活动编辑作用域。
- 自身和祖先未锁定、未隐藏。
- 图片已解码，且没有正在进行的替换、指针变换或文本编辑。
- `fit` 为 `cover`。

入口为双击图片，或属性面板中的“裁剪”按钮。形状图片填充继续显示“调整取景”。`contain` 模式下“裁剪”禁用，并提示先切换到“填满”。

### 5.2 裁剪画面

进入后隐藏普通选择框、缩放柄和旋转柄，显示专用裁剪层：

- 裁剪框内的图片保持正常亮度。
- 框外仍属于原图的部分可见，并覆盖半透明暗层。
- 裁剪框四边和四角显示 PowerPoint 风格黑色裁剪柄。
- 黑色柄的可见尺寸不随画布缩放变化，实际命中区域至少 24px。
- 裁剪框使用细实线，不显示现有三等分网格。
- 鼠标位于图片画面时显示移动光标，位于裁剪柄时显示与方向一致的缩放光标。

裁剪层使用两份引用同一缓存资源的图片：底层显示完整压暗原图，上层按裁剪框裁切并显示正常亮度。活动场景中的原图片节点在会话期间隐藏视觉内容但保留布局和身份，避免重复叠加。裁剪层属于 `freeform-ui-only`，不得进入缩略图和导出。

### 5.3 完成规则

以下操作都表示完成并保留当前裁剪：

- 点击裁剪目标和裁剪工具栏以外的画布区域。
- 按 `Escape`。
- 按 `Enter`。
- 点击工具栏“完成”。

`Escape` 不再取消独立图片裁剪。用户需要恢复时，完成后使用一次撤销；因为整次裁剪只产生一条历史记录，所以撤销会完整回到进入前状态。

形状图片填充仍沿用现有“完成 / 取消”和 `Escape` 取消语义，不随独立图片裁剪改变。

`pointercancel`、窗口失焦或触控笔流中断只撤回当前手势到上一次已落定的会话草稿，不退出裁剪，也不改写文档。

如果在 `gesturing` 中收到 `Escape`、`Enter`、外部点击、“完成”或同一作用域内的页面/工作区切换，先同步结算当前手势：取消待执行的 animation frame，用已经记录的最新指针位置再运行一次纯几何计算，把结果写入会话草稿，释放 pointer capture 和事件监听，然后执行完成。不能直接提交上一帧状态。若收到 `pointercancel`、窗口失焦或触控笔流中断，则取消待执行帧、释放指针所有权并恢复本段手势开始草稿，仍停留在裁剪模式。

如果草稿作用域已改变，或者目标、图片源、路径、锁定、隐藏或解码状态已经失效，则无论当前是否在手势中，都取消待执行帧、释放指针所有权并丢弃整次会话，不结算、不提交，也不向新作用域写入开始快照。

### 5.4 控件与窄视口

顶部裁剪条只保留“比例”和“完成”，不显示缩放滑杆、加减按钮或“取消”。工具栏点击不触发外部点击完成。

在 520px 及以下视口继续临时收起普通工具栏和两侧面板。裁剪条、裁剪框和必要的框外原图必须保持在可视工作区内；不得产生页面横向滚动。框外原图超出工作区的部分可以被工作区裁掉，但不能推大布局。

八个裁剪柄提供可访问名称和键盘入口。裁剪柄获得焦点后，方向键移动对应边 1 个本地像素，`Shift` 为 10 个；边柄同时按住 `Ctrl` 时执行对称调整。无效或已达边界的键盘操作保持原引用。

## 6. 会话、渲染与性能

独立图片裁剪不再在每个 `pointermove` 上调用 `replaceCurrent`。工作区维护一个独立的临时裁剪会话：

```text
idle -> cropping -> gesturing -> cropping
cropping -> finish -> idle
gesturing -> settle -> finish -> idle
gesturing -> rollback -> cropping
cropping | gesturing -> invalidate -> idle
```

每个手势按以下顺序执行：

1. `pointerdown` 固定本段手势的起点草稿、矩阵和指针所有权。
2. `pointermove` 只记录最新指针位置。
3. 每个 animation frame 最多计算并写一次裁剪层 DOM 样式。
4. `pointerup` 把最终合法结果写入会话草稿，并触发一次 React 状态同步。
5. 完成裁剪时才把节点几何和 `framing` 作为一次原子 action 写入文档。

这样一段包含上百次 `pointermove` 的拖动不会产生上百次文档克隆和 React 提交。DOM 快速路径与纯函数结果必须一致；`pointerup` 后由 React 渲染的稳定状态不能发生跳动。

完成独立图片裁剪的顺序固定为：

1. 按第 5.3 节结算活动手势，并取消待执行帧、pointer capture 和窗口监听。
2. 再次核对草稿作用域、活动页面、完整路径、节点类型、图片源、`fit`、锁定、隐藏和解码身份。
3. 把会话草稿转换成一个同时包含 `x/y/width/height/framing` 的内部原子 action。
4. 若 action 与开始节点在场景容差内相同，调用 `cancelLiveEdit(startDocument)` 保留开始文档引用，不写历史。
5. 若不同，先用 `replaceCurrent(action)` 把原子结果应用到当前文档；只有 action 确实命中且产生合法新节点后，才调用一次 `commitLiveEdit(startDocument)`。
6. 清理裁剪会话并恢复普通命令。action 未命中或归一化拒绝时不提交历史，保持开始文档并显示现有操作错误。

页面、草稿、账号或工作区切换必须按活动会话种类分派：有效的独立图片裁剪先按上述顺序完成再切换；现有形状图片取景仍调用 `cancelFramingThenTransition`，恢复会话开始值再切换。若权威状态已经改变作用域或使目标失效，两类会话都只清理临时状态，绝不能把旧快照或旧裁剪结果写进新文档。

裁剪期间继续禁用保存、导出、撤销/重做、节点结构修改、换图、锁定、隐藏和普通变换。完成后恢复原有命令状态。

## 7. 组件与文件边界

新增或调整的职责如下：

- `src/freeform/imageCrop.ts`：纯裁剪几何、边柄约束、比例预设和几何/取景反算。
- `src/freeform/ImageCropOverlay.tsx`：框内/框外双层图片、黑色裁剪柄、指针和键盘入口。
- `src/freeform/useImageCropSession.ts`：临时会话、单帧调度、手势所有权、完成和失效清理。
- `src/freeform/imageFraming.ts`：继续负责共享的原图渲染与平移计算；不放 React 或历史逻辑。
- `src/freeform/FreeformWorkspace.tsx`：选择目标、接入会话、外部点击完成和命令阻断。
- `src/freeform/document.ts` 与相关 action 类型：独立图片几何和 `framing` 的原子更新。
- `src/styles.css`：裁剪层、黑色柄、暗层、光标和响应式布局。

`FreeformWorkspace.tsx` 已经包含现有取景会话和大量编辑命令。本次不得把新的逐帧手势逻辑继续堆在该文件中；独立图片裁剪会话必须提取。形状取景可以暂时保留原实现，后续只有在不改变行为且测试覆盖完整时才共享底层 hook。

## 8. 错误与边界处理

- 图片尚未解码、自然尺寸无效或源正在替换时不能进入裁剪。
- 零尺寸、非有限尺寸、不可逆矩阵、失效路径和超出缩放契约的候选结果都返回原草稿，不产生 `NaN`、半个 patch 或空历史。
- 图片加载在会话中失败时，若仍属于同一作用域，丢弃会话并保持开始文档；显示现有操作错误。
- 异步换源的迟到结果继续按“草稿作用域 + slideId + ScenePath + 令牌”隔离。
- 形状取景、页面缩略图和导出继续使用 `FramedImage` 的现有 fallback，不因新裁剪层出现第二套保存结果。
- 本次没有新的网络错误类型，错误文案使用现有工作区通知通道。

## 9. 测试与验收

### 9.1 单元测试

- 八个裁剪柄的内裁、外扩和固定边规则。
- `Ctrl` + 四个边柄的对称调整；角柄不误用边柄规则。
- 最小尺寸、原图边界、`zoom = 1`、`zoom = 4` 和焦点四边界的连续投影。
- cover 主导轴在手势中切换时连续通过合法分段；角柄宽高同时越界时只能停在包含手势起点的合法连续区间末端。
- 候选框反算后，原图在画布中的矩形保持不动。
- 宽图、长图、方图与不同裁剪框比例下不露空白。
- 1:1、4:3、3:4、16:9、9:16 和原图比例。
- 旋转图片、缩放组、嵌套组和画布缩放下的屏幕位移逆变换。
- 零尺寸、非有限数和不可逆矩阵返回原引用。
- 几何与 `framing` 原子更新，同值 action 返回原节点引用。

### 9.2 Playwright 与视觉测试

- 独立图片双击和“裁剪”入口；形状仍显示“调整取景”。
